# Decisions

Record each decision and each resolved "verify" item: what was decided, why, source/date.

## Decided

### D1: Two Cargo workspaces (off-chain root, Anchor in `onchain/`)
- **Why:** On-chain crates (anchor-lang 1.2, solana 3.x, SBF build) and off-chain crates (yellowstone, sqlx, axum) would share one lockfile, which risks solana-* version conflicts. Separate workspaces also keep the 1.89 toolchain pin and fat-LTO release profile off the services.
- **When:** M0.

### D2: Commitment = `confirmed`
- **Why:** Lower latency than `finalized`. Reorg risk at `confirmed` is negligible in practice, and duplicate/orphan handling is idempotent anyway.
- **When:** M5. Revisit if orphaned rows are observed.

### D3: Attribution = first `failed:` log line, cross-checked with inner instructions
- **Why:** Frames emit `failed:` while unwinding outward, so the first one is innermost. When logs are truncated, attribution falls back to the root program with `attribution_confidence = low`.

### D4: Separate `anchor_framework` decode source
- **Why:** Anchor framework codes (< 6000) decode from a static table with no IDL. Keeping them apart from `idl` makes coverage numbers honest.

### D5: Toolchains pinned per workspace (M0, 2026-10-08)
- **Off-chain:** Rust 1.94.0 in `rust-toolchain.toml` at the root. **On-chain:** Rust 1.89.0 in `onchain/rust-toolchain.toml`, as generated by Anchor CLI 1.2.0.
- **Why:** Anchor's SBF build expects the toolchain it was scaffolded with. The services need newer crates and shouldn't be held back by it.

### D6: Program renamed `failscope` → `fail_target`, same program ID
- **Why:** Avoids a name clash with the tool's own crates. The ID `6MzbWCZgmdSrBwcUVypa4aGNKdck6r49jV7Y48AhPNey` is kept, because its keypair was renamed to `onchain/target/deploy/fail_target-keypair.json` (gitignored; back it up before deploying).

### D7: No-unwrap rule enforced by clippy
- `unwrap_used` / `expect_used` = deny at workspace level. `clippy.toml` allows both in tests. `main` returns `anyhow::Result`, so it doesn't need them either.
